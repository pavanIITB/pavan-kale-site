---
title: What can wait until version two
description: A way to decide which features belong in a first release.
date: 2026-11-26
sample: true
---

Begin with the job the first version needs to do. For a bottle with a reminder, one sensible test is whether a person notices the cue and drinks without needing to look anything up. List the things that would prevent that from happening, then make a version that handles them.

An attractive feature can still be worth deferring. Ask whether it changes the main behavior, helps somebody recover from a common mistake, or lets you learn something at the first release. If you can test the idea separately on a rough build, that is a good way to keep collecting evidence while the main version moves ahead.

Give deferred ideas a short note and a reason. That way you can bring them back when the bottleneck actually changes. Later decisions get harder when the team has to rediscover what each idea was supposed to solve.
